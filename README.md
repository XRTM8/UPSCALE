# UPSCALE Studio

تطبيق لتحسين الفيديو محلياً، بنواة **Rust** وواجهة **Leptos/WASM + Tauri 2**. العربية افتراضياً مع الإنجليزية، وتصميم فحمي بزجاج ضبابي ونصوص تيتانيوم. لا تُرفع ملفاتك إلى خادم.

يعالج Windows الفيديو عبر FFmpeg بتكبير Lanczos وتنظيف الضوضاء وتعزيز التفاصيل وتوليد الإطارات اختيارياً. يستخدم Android معالج الفيديو في الهاتف لتصدير MP4 بدقة 1080p. يمكن مشاركة الناتج من قائمة مشاركة Android. نماذج التحسين بالذكاء الاصطناعي والنشر عبر حسابات المنصات قيد التطوير.

## تنزيل الإصدار

تجد ملفات [الإصدار على GitHub](https://github.com/XRTM8/UPSCALE/releases/latest). على Windows x64 اختر `setup.exe` للتثبيت وإدارة التحديث من زر **التحديثات**، أو `portable.exe` للتشغيل المباشر. إذا احتاج Windows إلى FFmpeg اضغط **تجهيز محرك الفيديو** لتنزيل الحزمة والتحقق من بصمتها.

على Android 10 فأحدث، اختر `arm64-v8a.apk` للهواتف ARM64 أو `universal.apk` للمعماريات الأربع. النسختان بديلان للتطبيق نفسه ويمكن تثبيت إحداهما فوق الأخرى. يحفظ Android الناتج في `Movies/UPSCALE` بعد التحقق من الدقة والمدة والصوت.

## ما يعمل

- استيراد MP4 وMOV وM4V وMKV وWebM وAVI من نافذة النظام، مع فحص الخصائص بواسطة ffprobe.
- معاينة الأصل، ثم معاينة الملف الناتج والتبديل بينهما بعد التصدير الفعلي.
- قوالب إخراج رأسي وأفقي، وملاءمة الصورة كاملة أو قصها صراحةً، و1080p أو 4K حسب القالب.
- تصدير MP4/H.264/AAC، وتقدم مستمد من FFmpeg، وإلغاء حقيقي للمهمة.
- فحص أبعاد الملف الناتج ومدته ووجود الصوت قبل إعلان الاكتمال.
- حماية المصدر، ورفض الكتابة فوق ملف موجود، وتنظيف الملفات المؤقتة عند الإلغاء والفشل.
- خطوط وأيقونات محلية؛ لا تحتاج الواجهة إلى CDN عند التشغيل.

## البناء على Windows

المتطلبات: Windows 10/11 وWebView2 وNode.js 22 أو أحدث وpnpm. لتجهيز أدوات Rust وMinGW وTrunk وFFmpeg داخل `.tools` دون تغيير PATH النظام أو طلب صلاحيات مدير:

```powershell
.\scripts\bootstrap-windows.ps1
.\scripts\dev.ps1
```

يمكن أيضاً استخدام أدوات Rust/MSVC وWindows SDK المثبتة بالطريقة المعتادة مع `rustup target add wasm32-unknown-unknown` وTrunk 0.22.1 وFFmpeg/ffprobe على PATH، ثم:

```powershell
pnpm install --frozen-lockfile
pnpm assets
pnpm tauri dev
```

لإنشاء ملف التطبيق:

```powershell
.\scripts\build.ps1
```

الناتج في `target/release/upscale-studio.exe`. يبحث التطبيق عن محركه المجهّز من الواجهة أو عن FFmpeg وffprobe على PATH أو في مجلد `tools` بجانب التطبيق. يمكن تحديد مساريهما بمتغيري `UPSCALE_FFMPEG` و`UPSCALE_FFPROBE`.

لتشغيل النسخة المبنية بأدوات المشروع المحلية دون تشغيل خادم التطوير:

```powershell
.\scripts\run.ps1
```

للمعاينة في المتصفح فقط: شغّل `trunk serve`. يمكن اختيار فيديو محلي ومعاينته، بينما يُعطّل التصدير لأنه يعتمد على تطبيق الحاسب.

## التحقق

```powershell
.\scripts\check.ps1
```

تحتاج اختبارات خط المعالجة إلى FFmpeg وffprobe. تغطي فحص المصدر والدوران ومعدل الإطارات، وصحة قوالب الإخراج، وتصديراً حقيقياً مع الصوت، وحفظ المصدر، والإلغاء، ومنع استبدال الملفات الموجودة. يوجد أيضاً CLI لاختبار المحرك:

تستخدم اختبارات الواجهة Edge المثبت على Windows، أو المسار المحدد بمتغير `UPSCALE_BROWSER_PATH`. تفحص اللغتين وحفظ التفضيلات والقوالب، و24 حالة عرض ولوحات، واستيراد فيديو محلي فعلي دون الادعاء بتصديره من المتصفح. وتفحص معلومات الأصل والنتيجة و8 أحجام عرض بعد اكتمال المهمة بواسطة نقل أوامر اختباري؛ اختبار التشفير الفعلي منفصل في اختبارات Rust.

```powershell
cargo run -p upscale-core --bin upscale-cli -- probe 'video.mp4'
cargo run -p upscale-core --bin upscale-cli -- export 'video.mp4' 'video_upscaled.mp4'
```

## البنية

| المجلد | المسؤولية |
|---|---|
| `crates/upscale-types` | عقود البيانات المشتركة بين الواجهة والمحرك |
| `crates/upscale-core` | تحليل الفيديو وخطة التصدير والعامل والإلغاء وCLI |
| `crates/upscale-ui` | واجهة Leptos مكتوبة بـRust وتخزين تفضيلات المستخدم |
| `src-tauri` | نافذة الحاسب وحوارات الملفات وصلاحيات المعاينة وربط المحرك |
| `public/assets` | خطوط وأيقونات مع ملفات تراخيصها |
| `scripts` | تجهيز الأدوات والبناء والتحقق |

تصل أوامر المعالجة إلى ملفات اختارها المستخدم، باستخدام معرّفات داخلية. لا تستقبل واجهة التصدير أمراً shell أو مسار مصدر حراً. يُسمح لبروتوكول المعاينة بقراءة ملفات محددة، دون منح وصول عام إلى القرص.

## استمرارية التوقيع والإصدارات

يبني GitHub Actions ملفَي Windows وحزمتَي Android من نفس الالتزام. تُوقّع الحزم محلياً من مجلدي `upscale-windows-release-input` و`upscale-android-release-input` بعد تنزيلهما وفكهما:

```powershell
.\scripts\sign-release.ps1 -WindowsArtifacts <windows-directory> -AndroidArtifacts <android-directory>
```

يستخدم Android معرّف `com.xrtm8.upscale` وشهادة إصدار ثابتة. ارفع `versionCode` مع كل إصدار وفق `major × 1000000 + minor × 1000 + patch`، وطبّق القيمة نفسها على الحزمتين. يبقى مفتاح Tauri العام ثابتاً في `src-tauri/tauri.windows.conf.json`. يتحقق المحدّث من توقيع المثبّت ورقم نسخته قبل التنفيذ. حمّل الملفات الأربعة وملف التوقيع و`latest.json` و`SHA256SUMS.txt` معاً في إصدار GitHub الموافِق لرقم النسخة.

مفاتيح الإصدار وكلمات مرورها المحمية بحساب Windows محفوظة في `%LOCALAPPDATA%\UPSCALE\Signing`. لإنشاء نسخة قابلة للنقل، شغّل الأمر التالي واختر عبارة مرور تحفظها منفصلة عن الملف. استخدم الأمر نفسه مع `-Restore` على جهاز التوقيع الجديد.

```powershell
.\scripts\signing-backup.ps1 -BackupPath 'D:\upscale.upscale-signing-backup'
```

توقيع Tauri مخصص للتحقق من التحديثات، وشهادة Authenticode غير مضافة لهذا الإصدار.

## حدود المعالجة

يتطلب HDR مسار تحويل ألوان مخصصاً. توليد الإطارات خيار في Windows وقد يزيد وقت التصدير. يعتمد Android على الترميزات المدعومة في الجهاز. تعمل مهمة التصدير داخل التطبيق وتحتاج إلى إعادة التشغيل من البداية إذا انتهت العملية.
